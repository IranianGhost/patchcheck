# راهنمای فهم معماری و دفاع

هر عضو باید مستقل و بدون ابزار مولد پاسخ بتواند مسیر زیر را از روی شواهد
توضیح دهد: config → snapshot دقیق → چهار build → اجرای محدود → oracle مستقل
و مشاهده → replay → کوچک‌سازی → corpus رگرسیون → گزارش و تصمیم.

تصمیم‌های قابل دفاع: جداسازی Release/Sanitized؛ حفظ باینری ورودی و خروجی؛
تمایز سیگنال از کد خروج و خطای Runner؛ unknown به‌جای حدس؛ مرجع مستقل؛
تقدم ۳۰،۱۰،۲۰،۴۰،۰؛ تفاوت smoke موفق با اعتبارسنجی وصله؛ و محدودیت ادعای
«در آزمون‌ها دیده نشد». شناسهٔ image، commit به‌همراه dirty snapshot و hash
باینری تعیین می‌کنند دقیقاً چه چیزی آزمایش شده است.

تمرین تغییر محدود: افزودن ورودی معتبر فقط از طریق config؛ تغییر رفتار
انتظاررفتهٔ یک ورودی نامعتبر و مشاهدهٔ اثر oracle؛ ایجاد شکست compiler و
توضیح کد۳۰؛ بررسی سه replay و علت unstable؛ افزودن predicate با امضای
ناهمسان و توضیح رد آن؛ و دنبال‌کردن یک hunk تا شواهدی که هنوز برای علیت
کافی نیست. خروجی تمرین باید با فرمان و artifact واقعی ثبت شود.

طبق صورت کار، دفاع مستقل ۳ امتیاز معماری/سهم، ۳ امتیاز تحلیل شواهد و
۴ امتیاز تغییر محدود دارد. مشارکت مؤثر، حداقل ۵ از۱۰ و حداقل۱ در هر محور
لازم است. این راهنما جای مشارکت یا دفاع واقعی را نمی‌گیرد.
